# 📊 Flujo de Negocio y Procesos — Project Planner

Este documento modela visualmente los procesos de negocio corporativos, la arquitectura de integración y el ciclo de vida del sistema **Project Planner** mediante diagramas estándar **Mermaid** concisos, completamente citados y compatibles con Obsidian y exportación a PDF.

---

## 1. 🏢 Flujo de Negocio: Planificación y Aprobación (Fases 1 y 2)

Representa el ciclo desde la formulación inicial de la propuesta hasta la asignación de recursos y especialistas:

```mermaid
flowchart TD
    Start(["Inicio: Solicitud de Proyecto"]) --> Reg["1. Registro de Proyecto en Plataforma"]
    Reg --> EvalPresupuesto{"¿Presupuesto > $100,000?"}
    
    EvalPresupuesto -- Sí --> RevDirectiva["Revisión por Comité Directivo"]
    EvalPresupuesto -- No --> AprobLider["Aprobación Directa Líder Técnico"]
    
    RevDirectiva --> Dictamen{"¿Aprobado?"}
    Dictamen -- No --> Rechazado(["Proyecto Rechazado / Archivado"])
    Dictamen -- Sí --> ConfigPlan["2. Definir Hitos Globales y Calendario Maestro"]
    AprobLider --> ConfigPlan
    
    ConfigPlan --> SelArea["3. Seleccionar Área Técnica"]
    SelArea --> AsigEquipo["4. Asignar Especialistas y Líder de Proyecto"]
    AsigEquipo --> FinFase(["Pasar a Fase Operativa"])
```

## 2. 🔨 Flujo de Negocio: Ejecución y Cierre (Fases 3 y 4)

Control de tareas en campo, verificación de ruta crítica, auditoría y cierre contable:

```mermaid
flowchart TD
    StartOp(["Inicio Fase Operativa"]) --> Desglose["1. Desglose en Órdenes de Trabajo"]
    Desglose --> RutaCritica["2. Identificar Ruta Crítica y Holgura 7d"]
    RutaCritica --> Ejecucion["3. Ejecución de Tareas por Especialistas"]
    Ejecucion --> ControlAvance["4. Monitoreo de Avance y Costos"]
    
    ControlAvance --> CheckRiesgo{"¿Riesgo de Atraso > 7d?"}
    CheckRiesgo -- Sí --> Opt["Algoritmo de Optimización / Fast-Tracking"]
    Opt --> Ejecucion
    CheckRiesgo -- No --> CheckFin{"¿100% de Tareas Completadas?"}
    
    CheckFin -- No --> Ejecucion
    CheckFin -- Sí --> Liquidacion["5. Liquidación y Auditoría Final"]
    Liquidacion --> Webhook["6. Disparo Webhook a Make (Alertas)"]
    Webhook --> FinTotal(["Proyecto Concluido con Éxito"])
```

## 3. 🔄 Ciclo de Vida del Proyecto (Estados)

Transiciones de estado oficiales gobernadas por el backend relacional:

```mermaid
stateDiagram-v2
    [*] --> PLANNING : Alta de proyecto
    PLANNING --> IN_PROGRESS : Aprobación formal
    PLANNING --> CANCELLED : Desestimado
    IN_PROGRESS --> STAND_BY : Pausa operativa
    STAND_BY --> IN_PROGRESS : Reanudación
    IN_PROGRESS --> COMPLETED : 100% tareas completadas
    STAND_BY --> CANCELLED : Cancelación definitiva
    COMPLETED --> [*] : Cierre contable y archivo
    CANCELLED --> [*] : Archivado
```

## 4. ⚡ Secuencia de Integraciones Externas (Make & Autodesk APS)

```mermaid
sequenceDiagram
    autonumber
    actor U as Líder / Especialista
    participant F as Frontend
    participant B as Django API
    participant M as Make / Webhook
    participant A as Autodesk APS (BIM)

    Note over U,M: Flujo 1: Notificación de Creación
    U->>F: Guardar nuevo proyecto
    F->>B: POST /api/projects/
    B->>M: Webhook (project.created)
    M-->>U: Notificación en Discord y Gmail

    Note over U,A: Flujo 2: Visualización BIM 3D
    U->>F: Consulta planos o modelo Revit (.RVT)
    F->>B: GET /api/integrations/aps/models/:id/
    B-->>F: Retorna URN del modelo procesado
    F->>A: Carga Autodesk Viewer con URN
    A-->>U: Renderizado 3D interactivo en navegador
```
